## 第 1 幕 · 开场钩子（0:00–0:40）

[画面] 实拍：手持遥控器对它说话；切电脑屏幕，微信输入框文字逐字上屏。快切两个场景：VSCode 里一句话、浏览器搜索框一句话。最后镜头拉远——人在沙发上，电脑在书桌上。

[字幕] 这不是麦克风。

> 口播：

你现在看到的这支"麦克风"，其实是它——小米蓝牙遥控器 2 Pro，就是电视柜里那个 99 块钱的电视遥控器。按住语音键说话，一松手，文字就上了屏。回微信、给 AI 编程工具念需求、搜东西，人都不用坐在电脑前面，整个房间都是它的收音范围。

今天这期视频，讲讲我怎么把它变成 Windows 的无线麦克风。项目已经开源，叫 MiVoiceMic。

## 第 2 幕 · 来龙去脉（0:40–2:20）

[画面] 遥控器按键特写（重点语音键）；电视语音助手界面（可用手机录电视或找官方图）；随后切屏：GitHub 上 remote-mic-app 和 RemoteMapper 两个仓库页面；最后本项目仓库首页。

[字幕] ATVV：小米私有的语音协议 / Windows 只把它当键盘

> 口播：

事情要从一台小米电视说起。这个遥控器上的语音键，在电视上特别好使——按住说话，电视就听懂了。我就在想：电脑要是也能用它就好了。想象一下，躺在沙发上给 AI 念需求、回消息，这才叫遥控器的完全体。

但插上 Windows 一试，不行。系统只把它当成一个普通键盘：方向键、确定键倒是能用，语音键一按，屏幕上疯狂刷新——因为 Windows 把它识别成了 F5，网页刷个不停。

查了资料才明白，这个语音键在电视上走的是小米私有的 ATVV 协议：按住的时候，遥控器通过蓝牙低功耗，持续把压缩好的语音数据推给电视。Windows 根本不知道怎么跟它"对话"。

好消息是，这条路已经有人趟过了。macOS 上有一位作者做了个现成的开源应用，叫 remote-mic-app，完美复刻了电视上的体验；Windows 上另一位作者做了 RemoteMapper，不但逆向了 ATVV 协议，还写了个内核驱动，把 Windows 不认识的按键救了回来。地图都画好了，我就在两位前人的基础上，写了 Windows 上的完整实现——MiVoiceMic。项目开源，GPL 协议。

## 第 3 幕 · 工作原理（2:20–4:50）

[画面] 管线动画逐段点亮：遥控器 →（BLE·ATVV）→ MiVoiceMic（ADPCM 解码）→（waveOut）→ VB-CABLE 虚拟声卡 →（切默认麦克风）→ 微信输入法/Win+H → 文字上屏。每讲一段点亮一段；穿插真实运行日志滚动的空镜。

[字幕] 整套方案最取巧的一点：我不做语音识别

> 口播：

先说整个方案最取巧的一点：我一行语音识别的代码都没写。Windows 上的输入法早就把"按住说话、松开上字"做得很好了——微信输入法、系统自带的 Win+H 都是。所以 MiVoiceMic 要做的只有一件事：**伪装成输入法想听到的那个麦克风，然后替你按下语音热键。**

拆开是四步。

第一步，跟遥控器对话。按 ATVV 协议握手，告诉遥控器"我要开麦了"。遥控器就开始持续往外推语音数据——16 千赫兹采样的 ADPCM 压缩音频，每 15 毫秒一小包，通过蓝牙低功耗传过来。我在程序里把它解码成 PCM，顺手做了去毛刺、低通和自动增益，让音量听起来正常。

第二步，把声音送进一块"假声卡"。这里用到一个免费的虚拟声卡驱动，叫 VB-CABLE。它在系统里凭空造了一对设备：播放端叫 CABLE Input，录音端叫 CABLE Output。播放端放进去什么声音，录音端就能录到什么。我把解码好的语音推给播放端——这时候系统里就有一台"正在出声的麦克风"了，虽然它其实根本不是麦克风。

第三步，偷天换日。微信输入法录音的时候，用的是系统默认麦克风。所以我在注入热键之前的一瞬间，把系统默认麦克风临时切换成刚才那台"假麦克风"——CABLE Output。这里调的是一个微软没公开的系统接口，各种切音量的工具其实都在用。等你松开语音键，再悄悄切回来，全程无感。中间还留了 120 毫秒的缓冲，给输入法一点感知设备变化的时间。

第四步，替你按键。用系统的 SendInput，把语音热键"按"下去——比如微信输入法默认的右 Alt 加逗号，或者 Win+H。按住多久，就替你按多久；你松开语音键，程序松开热键、恢复原来的麦克风，输入法识别完，文字上屏。

[画面] 演示一次完整流程：按住语音键说一句话，屏幕展示文字上屏，与口播收尾同步。

> 口播（收尾）：

整个过程说起来绕，体感上就是遥控器上的语音键"穿透"到了电脑上——跟在电视上一模一样的用法。

## 第 4 幕 · 功能演示（4:50–7:00）

[画面+口播，边操作边讲]

[画面] 主窗口 · 连接页：设备卡显示"已连接"和电量；按住语音键说话，电平条跳动；指一下今日使用统计。

> 口播：

主界面一共四页。第一页是连接与语音：遥控器的连接状态、电量，说话的时候有个实时电平条，下面还有今日使用的次数和时长统计——我发现自己一天居然要用上百次。

[画面] 语音热键区域：点击捕获框，直接按下组合键；切换"按住跟随/点按开关"；点"测试热键"。

> 口播：

语音热键这里，预设了微信输入法和 Win+H，也可以点这个捕获框，直接按你想要的组合键——程序里输什么组合键都行，Win 键也支持。注入方式有"按住跟随"和"点按开关"两种，配不同习惯的输入法。

[画面] 切到按键映射页：整机矢量图，按键卡片环绕；点开一个按键编辑：选"长按"手势，动作设为"任务视图"；保存后按遥控器方向键演示；再演示"打开应用"。

> 口播：

第二页是我最喜欢的按键映射。遥控器上十三个键，每个键都能单独配"点按"和"长按"两个手势，动作可以是单键、组合键、打开任务视图、启动应用、跑命令。比如我把确定键点按设成回车，长按设成任务视图，躺沙发上就能切换窗口。

这里有个细节值得说：程序靠 Raw Input 按设备的 VID 和 PID 判断"这个键是不是遥控器按的"，所以映射只对遥控器生效——你物理键盘上的方向键、F5，完全不受影响。

[画面] 环境自检页全绿一屏；切命令行演示 `--check` 和 `--e2e`（出现 PASS）。

> 口播：

第三页环境自检，蓝牙、配对、虚拟声卡、输入法，逐项检查。同样的检查在命令行也有——开发的时候我给自己定了个规矩：先 `--check` 确认环境，再 `--e2e` 做一次无遥控器的全链路自测，用系统 TTS 合成一段中文，走完"解码、声卡、切麦"整条管线，看到 PASS 才算环境 OK。这套东西让我联调的时候，一眼就能分清是环境的问题还是遥控器的问题。

[画面] 关闭主窗口 → 托盘气泡；右键托盘图标展示菜单；双击托盘恢复窗口。

> 口播：

关掉窗口它会缩到托盘继续干活，托盘菜单里可以随时切热键预设、重新连接遥控器。

## 第 5 幕 · 踩坑故事（7:00–8:30）

[画面] 投屏 docs/NON-STANDARD-KEYS.md 里的表格：按键 → HID 用法 → 结果；"丢弃点在内核"示意；随后三层 bug 用三张简笔画逐层揭开。

[字幕] 有 7 个键，Windows 在内核里直接扔掉了

> 口播：

讲两个印象最深的坑。

第一个：这个遥控器有 7 个键，在 Windows 上是"超自然现象"级别的消失——返回、主页、菜单、直播、电源、音量加减，按了 absolutely 没反应，任何软件都收不到。原因在 docs 里我专门写了篇分析：这 7 个键发的 HID 用法是非标准的，Windows 的键盘类驱动在内核里找不到对应按键，直接丢弃。注意，是内核——所以全局钩子、Raw Input、AutoHotkey、改注册表，全部无能为力，事件根本到不了用户态。

唯一的办法是在内核里拦。前人 RemoteMapper 写了个过滤驱动，在这些报告到达键盘驱动之前，把它们改写成 F13 到 F19——Windows 认识的键。我把这个驱动内置进了程序，映射页里一键安装。但代价你得知道：测试签名驱动和 Secure Boot 互斥，所以得关掉 Secure Boot、重启两次才能装上。这也是这个项目最大的遗憾——转正需要一个 EV 证书去微软做正式签名，个人项目暂时够不着。

第二个坑更阴险，是个三层套娃的 bug。按键映射要判断"按键来自遥控器还是物理键盘"，我用的是 Raw Input 查设备路径。第一层：查询设备名的 API 常量，我抄错了一个值，导致每次查询都失败；第二层：查名字前大家习惯先用"传空指针探长度"的两段式调用，但这个用法对"查设备名"恰好不成立，传空必失败——两行代码错在同一个函数里；第三层：就算查询成功了，我拿 USB 风格的路径去匹配，而蓝牙 HID 设备的路径长得完全不一样，照样匹配不上。三层错误，层层掩盖，最终表现就是一句话："映射在真机上静默失效"，日志里没有任何报错。最后是拿物理键盘、USB 路径、BLE 路径三方对照才层层剥出来的。教训写在代码注释里了：静默失效的 bug，要沿着数据流的每一层做单元验证，不能只看最终现象。

## 第 6 幕 · 未完成与展望（8:30–9:30）

[画面] 字幕逐条出现 + 简单动画。

[字幕] 诚实清单

> 口播：

照例说说还没做完的部分。

驱动那关：Secure Boot 开着的电脑装不了内核驱动，那 7 个键就用不了——好消息是语音输入完全不依赖它。
音频那关：遥控器固件只给 16 千赫兹编码，8 千赫兹的老设备直接握手失败，我没做重采样。
体验那关：连接期间物理键盘的 F5 也会被吞掉，虽然留了开关，但不算优雅；固件决定了只有"按住说话"，没有持续录音模式；微信输入法要求有输入框焦点，没焦点识别了也不上屏。
工程那关：切默认麦克风用的是未公开接口，Windows 哪天改了就可能失效；按键归因靠毫秒级的时间窗关联，极端情况下可能漏判。

展望：给驱动走微软的正式签名、接入本地语音识别彻底摆脱输入法依赖、做个正经的安装包。有兴趣欢迎一起来搞。
